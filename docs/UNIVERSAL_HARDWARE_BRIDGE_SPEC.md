# 通用硬件接口与多术式抽象层架构
## Universal Hardware Bridge & Multi-Surgical Abstraction Layer

**核心命题：** 手术千差万别（脊柱打钉、膝关节截骨、颅脑穿刺、颌面重塑），规划算法完全不同，但**最终如何统一接入各种传感器与机械臂**？

---

## 1. 核心解耦架构：从“万种手术”到“统一硬件”

之所以很多手术软件无法通用，是因为它们把“骨科截骨”和“某款机械臂的 SDK”硬编码绑定在了一起。

在 NodeSurg 平台中，我们采用**三层解耦架构 (Three-Tier Architecture)**：

```
+-----------------------------------------------------------------------------------------+
|                                  三层解耦手术体系                                       |
|                                                                                         |
|   【顶层：千姿百态的专科规划层】                                                        |
|   +-------------------+  +-------------------+  +-------------------+                   |
|   | 脊柱椎弓根钉规划  |  | 膝/髋关节置换规划 |  | 神经外科穿刺规划  |  (不同术式节点包)     |
|   +---------+---------+  +---------+---------+  +---------+---------+                   |
|             │                      │                      │                             |
|             └──────────────────────┼──────────────────────┘                             |
|                                    ▼                                                    |
|   【中层：通用手术几何与约束指令集 (USCS)】                                             |
|   不管什么手术，最终输出被归一化为 4 大标准图元：                                       |
|   1. 目标位姿矩阵 (Target Pose 4x4)      2. 运动刀路轨迹 (Toolpath Curve)               |
|   3. 空间虚拟夹具 (Virtual Fixtures)     4. 配准转换基准 (Registration Matrix)          |
|                                    │                                                    |
|                                    ▼                                                    |
|   【底层：通用硬件驱动与桥接层 (Hardware Bridge)】                                      |
|   +-------------------------------------+  +-------------------------------------+      |
|   |          传感器桥接节点             |  |            机械臂桥接节点           |      |
|   |  • NDI 光学定位 (Polaris/Vega)      |  |  • 协作臂 (UR, Franka, KUKA, 遨博)   |      |
|   |  • OptiTrack / 双目视觉相机         |  |  • 骨科专用摆锯/铣削机械臂           |      |
|   |  • 电磁定位 (NDI Aurora)            |  |  • 机械臂导向套筒定位                |      |
|   |  • 六维力矩传感器 (ATI loadcell)    |  |  • 穿刺执行机构 (Stepper/Linear)     |      |
|   +-------------------------------------+  +-------------------------------------+      |
+-----------------------------------------------------------------------------------------+
```

## 2. 为什么任何手术都能统一接入机械臂与传感器？

不同专科医生口中的“手术术语”完全不同，但**在三维数学与机器人动力学眼里，本质只有 4 种对象**：

| 专科手术术语 | 临床意义 | 归一化后的硬件通用图元 (USCS) | 机械臂 / 传感器如何执行 |
|---|---|---|---|
| **脊柱：椎弓根进针钉道** | 螺钉穿过椎弓根进入椎体 | **空间直线轴线 (Linear Trajectory)** | 机械臂末端套筒自动对准该轴线，锁定旋转，允许医生沿轴线单向推进钻孔。 |
| **关节：胫骨/股骨截骨面** | 截除磨损软骨，为假体腾出平面 | **平面与外轮廓 (Plane + Boundary)** | 机械臂摆锯被约束在该平面内摆动，超出骨骼边界时机械臂电机产生**主动阻尼排斥 (Virtual Fixture)**。 |
| **神经外科：脑深部电极植入 (DBS)** | 极高精度的靶点定位 | **空间靶点与进针角度 (Target Point + Angles)** | 机械臂以微米级精度将导向孔送至靶点入颅轨迹，传感器实时监控微小位移。 |
| **颌面：下颌骨肿瘤切除** | 多段拼接复位 | **多段位姿变换组 (Rigid Transforms $SE(3)$)** | 机械臂协助医生将切下来的腓骨依次对齐到规划的吻合位姿。 |

## 3. 节点画布上的“乐高式”自由组合 (The LEGO Experience)

这种解耦给科研人员和临床工程师带来了无与伦比的自由度：**即插即用**。

### 场景 1：同一套脊柱规划，连接不同品牌硬件
- **科研团队 A（低成本）：**
  `[脊柱打钉规划节点]` ──► `[双目摄像头节点]` ──► `[UR5 协作机械臂节点]`
- **医院中心 B（高端配置）：**
  `[脊柱打钉规划节点]` ──► `[NDI Polaris 光学定位仪节点]` ──► `[KUKA LBR Med 医疗机械臂节点]`

> **用户价值：** 规划图完全不需要修改！只需要在末端把硬件节点连线换一下，系统就能自适应驱动不同的传感器和机械臂。

```

|                                节点画布中的即插即用                                     |

+-----------------------------------------------------------------------------------------+
```

## 4. 传感器与机械臂的标准化接入规范

为了确保平台能兼容全球主流的工业级与科研级硬件，NodeSurg 原生支持以下通信与协议栈：

### A. 传感器跟踪接口 (Tracking & Sensing Bridges)
1. **OpenIGTLink 协议 (医疗通用标准)：**
   - 与 NDI Polaris / Vega、Claron MicronTracker、SlicerIGT 无缝通信。
   - 传输频率：$60\text{ Hz} \sim 120\text{ Hz}$ 实时 6-DOF 刚体变换矩阵（Transform3D）。
2. **OptiTrack NatNet 协议：**
   - 高精度动捕多相机阵列，支持微创手术器械的高频姿态回传。
3. **力矩传感器输入 (FT Sensors)：**
   - 接入 ATI 或机械臂关节内建力传感器，支持规划层设置**力控安全阈值**（如接触力 $>15\text{ N}$ 自动急停）。

### B. 机械臂控制接口 (Robotic Actuation Bridges)
1. **ROS2 Control / MoveIt2 桥接：**
   - 科研界与新型医疗机械臂最主流的中间件体系，支持避障路径规划、逆运动学求解（IK Solver）。
2. **机械臂原厂实时接口 (Low-Latency Interfaces)：**
   - **UR RTDE** (Real-Time Data Exchange, $500\text{ Hz}$)
   - **KUKA FRI** (Fast Robot Interface, $1\text{ kHz}$)
   - **Franka FCI** (libfranka, 实时重力补偿与导纳控制)
3. **安全交互模式 (Interaction Modes)：**
   - **自主定位模式 (Autonomous Positioning)：** 机械臂自动移动到目标截面或靶点，等待医生确认。
   - **协同拖动示教模式 (Hand-Guiding with Virtual Fixtures)：** 医生用手推着机械臂移动，机械臂仅在规划好的平面或轴线上顺滑滑动，周围区域锁死（如同在无形的轨道里滑行）。

## 5. 对科研人员与设备厂商的终极价值

1. **研发生命周期缩短 $80\%$：**
   以往开发一台新的手术机器人，团队要花 2 年时间写专用的配准算法、规划软件和机械臂驱动。现在，团队只需专注于专科手术算法，底层的传感器与机械臂节点直接调用现成模块。
2. **真正做到“手术算法”与“硬件资产”解耦：**
   算法工程师可以在没有真机的情况下，通过节点连接“虚拟机械臂仿真器 (Virtual Robot Sim)”进行规划测试；到了真实手术室，把节点换成真实机械臂，即可无缝实装。
